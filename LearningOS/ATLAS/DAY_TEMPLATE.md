# ATLAS Day Template

각 Day는 아래 구조를 기본으로 합니다.

## 1. 오늘의 질문
기술 용어가 아니라 실제 문제로 시작합니다.

예: `모델 성능이 좋아졌는데, 정말 모델이 좋아진 걸까?`

## 2. 배경 이야기
오늘 개념이 왜 필요한지 쉬운 사례와 프로젝트 맥락으로 설명합니다.

## 3. 핵심 개념
용어를 한국어 직관 → 그림/표 → 영어 용어 순서로 설명합니다.

## 4. delayed-label-monitoring 연결
실제 README, 보고서, 실패 기록, 코드 구조 중 관련 사례를 선택해 연결합니다.

## 5. 실패 사례
가능하면 `docs/failures.md`의 실제 실패를 활용합니다.

```text
무슨 일이 있었나?
→ 왜 처음에는 몰랐나?
→ 어떤 신호가 이상했나?
→ 어떻게 확인했나?
→ 일반화 가능한 교훈은 무엇인가?
```

## 6. 실무 연결
현업 데이터 분석/MLOps에서는 이 개념을 어디서 사용하는지 설명합니다.

## 7. 오늘의 구조도
한 장짜리 텍스트 그림 또는 개념 지도를 만듭니다.

## 8. 확인 문제
암기 문제보다 상황 판단 문제를 사용합니다.

## 9. 오늘의 5문장
배운 내용을 자신의 말로 정리합니다.

## 10. 내일의 떡밥
오늘 생긴 한계를 다음 Day의 질문으로 연결합니다.
